<objective>
Build the autologon lifecycle: a per-deployment random password stored as an LSA
secret, arming bounded by `AutoLogonCount`, the boot-time reconcile, and the
teardown checklist — all behind `IRegistryService` and `ILsaService` so every
part of it is provable against fakes.

Purpose: this is the mechanism most likely to leave a real machine in a bad
state. MDT's cleanup is a task sequence step, so a failure before it leaves
autologon armed with a fleet-wide cleartext password. HDT tears down from a
`finally` **and** reconciles on every boot **and** bounds the count. This plan
builds the second and third of those; 03-04 wires the first.

### The registry write half

`IRegistryService` gains four methods, all recorded:

```
NewKey([string] $Path)                                                  idempotent
SetValue([string] $Path, [string] $Name, [object] $Value, [string] $Type)
RemoveValue([string] $Path, [string] $Name)                             idempotent
RemoveKey([string] $Path, [bool] $Recurse)                              idempotent
```

`$Type` is `String`, `ExpandString`, `DWord`, `QWord`, `Binary` or `MultiString`
— the `New-ItemProperty -PropertyType` names.

**Removing a value that is not there is not an error.** Teardown runs on machines
in unknown states, and a teardown that throws on the first absent value is a
teardown that does not finish.

The fake's existing **seeding** methods collide with the new interface, so rename
them first: `SetValue(path,name,value)` → `SeedValue(path,name,value)` and
`AddKey(path)` → `SeedKey(path)`, updating `New-HDTFakeRegistryService` and
every caller. Then add the four interface methods, which **do** record. Seeding
still does not (tests/helpers/README.md section 4).

### ILsaService

```
SetSecret([string] $Name, [string] $Value)   store LSA private data
GetSecret([string] $Name)  -> [string]|$null
RemoveSecret([string] $Name)                 idempotent
```

`New-HDTLsaService` is the real adapter: `Add-Type` once, guarded by
`if (-not ('HDTLsaInterop' -as [type]))`, then `LsaOpenPolicy` /
`LsaStorePrivateData` (a null data pointer deletes) / `LsaRetrievePrivateData` /
`LsaFreeMemory` / `LsaClose`, with `LsaNtStatusToWinError` turning a failure into
a `Win32Exception`. It is an **untested adapter** by DESIGN 12.2.3 — keep it
branch-free apart from the type guard and the status checks, and keep every
decision out of it.

The secret name Winlogon reads is `DefaultPassword`, with no `L$`/`M$` prefix —
the same name Sysinternals' `Autologon.exe` writes. HDT writes only that one.

`New-HDTFakeLsaService [-Secret @{...}] [-Journal]` is an in-memory dictionary
that records and never touches LSA.

**The real row in `LsaService.Contract.Tests.ps1` is skipped unless the session
is elevated AND `$env:HDT_ALLOW_LSA_TEST -eq '1'`**, printing a warning that says
so, and even then it only calls `GetSecret` on a name that does not exist. **The
suite never writes an LSA secret on the developer's machine.** Put the skip on a
`Context` inside the `Describe`, never on a `-ForEach Describe` (README F9).
`$IsWindows` does not exist under 5.1 — use
`[System.Environment]::OSVersion.Platform -eq 'Win32NT'`, and detect elevation
with `[Security.Principal.WindowsPrincipal]::new([Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)`.

### The deployment password

```
New-HDTDeploymentPassword [-Length 24] [-RandomNumberGenerator <object>] -> [string]
```

- Length 16-127, default 24.
- Alphabet: `A-Z`, `a-z`, `0-9` and the symbols `!#$*+-=?@_`. Everything else is
  excluded deliberately: `& < > " ' % ^ | \ / ` and space break either
  `unattend.xml`, a command line, or `%Var%` expansion, and a password that
  cannot survive being handled is worse than a shorter one.
- At least one character from each of the four classes, satisfying Windows
  complexity without a retry loop that could bias the distribution.
- Bytes come from the injected RNG (default
  `[System.Security.Cryptography.RandomNumberGenerator]::Create()`), mapped with
  **rejection sampling** — a byte at or above the largest multiple of the
  alphabet length is discarded and redrawn. Never `byte % length`, which biases
  the low end of the alphabet, and never `Get-Random`, which is not a CSPRNG.
- The value is returned and nothing else. **It is never logged, never written to
  the registry, and never included in a report.** The only places it lives are
  the LSA secret and `state.json`'s `deploymentPassword`, until teardown nulls it.

### Arming — `Set-HDTAutoLogon`

```
Set-HDTAutoLogon -Registry -Lsa -UserName -Password -RemainingLeg
                 [-DomainName] [-ResumeCommand] [-State] [-LogContext]
                 [-WhatIf]
```

Writes, in this order:

| Where | Value | Type |
|---|---|---|
| `HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon` | `AutoAdminLogon` = `1` | String |
| " | `DefaultUserName` = `-UserName` | String |
| " | `DefaultDomainName` = `-DomainName` or `''` | String |
| " | `AutoLogonCount` = `-RemainingLeg` | DWord |
| LSA | secret `DefaultPassword` = `-Password` | — |
| `HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce` | `HDTResume` = `-ResumeCommand` | String |

and **removes** any registry `DefaultPassword` it finds, because an image or
another tool may have left one and DESIGN 4.5.2's whole point is that the
password is not in the registry.

- `-RemainingLeg` is the number of autologons still needed — DESIGN 4.5.2's
  "exactly the number of legs remaining". The caller computes it; 03-04 computes
  it as the number of `Restart` steps left plus one.
- Default `-ResumeCommand`:
  `powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\HDT\Start-HDTResume.ps1`
- Updates `$State.autoLogon` when a state is given: `armed`, `userName`,
  `domainName`, `countSet`, `secretName`, `runOnceName`. It does **not** save the
  state — the caller owns the write order, and 03-04 saves immediately after.
- Logs one `reboot.arm` record with `data` carrying the user name and the count.
  **The password never appears in `data`, in the message, or anywhere else.**
- `SupportsShouldProcess`: `-WhatIf` writes nothing at all, registry or LSA.

### Reading — `Get-HDTAutoLogonState`

```
Get-HDTAutoLogonState -Registry -Lsa -> [pscustomobject] @{
    Armed; UserName; DomainName; Count; HasRegistryPassword; HasLsaSecret; RunOnceCommand }
```

`Armed` is `$true` when `AutoAdminLogon` is `1`. It reports `HasLsaSecret` as a
boolean, never the secret itself.

### Teardown — `Clear-HDTAutoLogon`, the DESIGN 4.5.3 checklist

```
Clear-HDTAutoLogon -Registry -Lsa [-FileSystem] [-State] [-StatePath]
                   [-UnattendPath <string[]>] [-LogContext] [-WhatIf]
    -> [pscustomobject] @{ Cleared = [string[]]; Failed = [object[]] }
```

The checklist, verbatim from DESIGN 4.5.3, each item attempted **independently**:

1. `AutoAdminLogon`
2. `DefaultUserName`
3. `DefaultDomainName`
4. `DefaultPassword` in the registry
5. `DefaultPassword` as an LSA secret
6. `AutoLogonCount`
7. the `RunOnce\HDTResume` entry
8. the staged unattend — `-UnattendPath`, defaulting to
   `C:\HDT\unattend.xml`, `C:\Windows\Panther\unattend.xml`,
   `C:\Windows\System32\Sysprep\unattend.xml`, each deleted through `IFileSystem`
   when it exists
9. `deploymentPassword` in `state.json` set to `$null`, and the state saved when
   `-StatePath` and `-FileSystem` were given

**One item failing must not stop the others.** Each is wrapped, the failure is
appended to `Failed` with the item name and the exception message, and the
function returns rather than throwing. A teardown that gives up halfway is how a
machine ends up armed with six of nine artifacts cleared.

It is idempotent: clearing an already-clear machine returns with an empty
`Failed` and does not throw. It logs one `reboot.teardown` record listing what it
cleared.

**Out of scope for M2, and it must be said out loud:** DESIGN 4.5.3's second half
— "then applies the final Administrator password policy: rotate, hand off to
LAPS, or disable" — needs a step type that M2 does not ship. Record it in the
summary as a phase 07 item and add it to `docs/ROADMAP.md` M6 in 03-05's docs
task. Leaving it unstated would be the difference between a documented gap and a
forgotten one.

### The boot-time reconcile — `Invoke-HDTBootReconciliation`

DESIGN 4.5.2: `Start-HDTResume.ps1` "reconciles on every boot: if the state
document says the run is finished, failed, or missing, it clears autologon, the
LSA secret, the `RunOnce` entry, and `C:\HDT\state.json` **before doing anything
else**."

```
Invoke-HDTBootReconciliation -StatePath -FileSystem -Registry -Lsa -Clock
                             [-LogContext] [-UnattendPath] [-MaxAgeHour 12]
    -> [pscustomobject] @{ Action = 'Resume'|'Teardown'; Reason; State }
```

| Condition | Action | Reason |
|---|---|---|
| the state file does not exist | Teardown | `no state document` |
| the state file cannot be read or parsed | Teardown | `unreadable state document` |
| `Test-HDTRunStateAbandoned` is true (finished, or stale past `-MaxAgeHour`) | Teardown | `run finished` / `run abandoned` |
| otherwise | Resume | `resuming at step <n>` |

Teardown calls `Clear-HDTAutoLogon` and then removes the state file itself.
Resume increments `leg`, logs `reboot.resume`, and returns the state — it does
**not** run the sequence; the caller does (03-04's `Start-HDTResume.ps1`).

The unreadable case is deliberate and is the one place `Import-HDTRunState`'s
throw is caught: on a boot, a corrupt state document is not evidence that a run
is alive, and the safe reading is "disarm". It is also the only branch here that
swallows an exception, so log it at `Warning` with the parse message.

### Hard safety rules — read before touching anything

- **Never touch `CM01` or `DC01`.** Filter every Hyper-V call to `HDT-*`

### Method

1. `Copy-Item C:\HDTLab\vms\HDT-PE-Test-osdisk.vhdx C:\HDTLab\scratch\autologon-spike.vhdx`
