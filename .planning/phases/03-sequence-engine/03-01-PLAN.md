<verified_facts>
Probed on this machine on 2026-08-13 under **both** pwsh 7.5.8 and Windows
PowerShell 5.1.26100.8655. These are facts; do not re-derive them.

- `Set-Content -Encoding UTF8` writes a **BOM under 5.1** (`239,187,191`) and
  **no BOM under pwsh 7** (`120,...`). `[System.IO.File]::WriteAllText($p,$t,(New-Object System.Text.UTF8Encoding($false)))`
  and `[System.IO.File]::AppendAllText` with the same encoding are BOM-free on
  both. **The real IFileSystem adapter uses the `System.IO.File` calls**, never
  `Set-Content`/`Add-Content`. This is SPIKES.md S6's UTF-16 `Tee-Object` trap in
  a different disguise.
- `[System.IO.File]::AppendAllText` **creates a missing file** but **throws** when
  the parent directory is missing (`MethodInvocationException` wrapping
  `DirectoryNotFoundException`). The adapter creates the parent first, matching
  `HDTFakeFileSystem.AddFile`, which already does.
- `[System.IO.Path]::GetFullPath('X:\HDT\Logs')` returns `X:\HDT\Logs` on a
  machine with no `X:` drive on both engines, so WinPE paths normalise fine in
  the fake filesystem on a dev box.
- `ConvertTo-Json -Depth 8` round-trips a nested `[ordered]` state document
  through `ConvertFrom-Json` on both engines; the result is a `PSCustomObject`
  tree (never `-AsHashtable`, which is banned).
- A `[datetime]` handed to `ConvertTo-Json` serialises as `\/Date(...)\/` under
  5.1 and ISO 8601 under 7 (02-03-SUMMARY). **Every timestamp this plan writes is
  formatted to a string first** with
  `.ToUniversalTime().ToString('o', [System.Globalization.CultureInfo]::InvariantCulture)`.
- A `ScriptMethod` that mutates `$this` works on both engines
  (`$this.Seq++` returned 1 then 2), so the log context can carry its own
  monotonic counter.
- `[System.Diagnostics.Stopwatch]::StartNew()` and
  `[System.Threading.Thread]::CurrentThread.ManagedThreadId` both exist on both
  engines.
- The CMTrace line built with a `-f` format string renders identically on both
  engines.

### The shared journal

Every fake already records into its own `$Operations`. That is enough to assert
what *one* service was asked to do and useless for asserting the order of
operations *across* services — which is exactly what DESIGN 12.2.1 demands of the
headline test. So every `New-HDTFake*` factory gains:

```
-Journal [System.Collections.ArrayList]
```

When supplied, the fake's `Record()` appends **in addition to** `$Operations`:

| Property | Meaning |
|---|---|
| `Sequence` | 1-based position in the journal, across every service |
| `Service` | the fake's service name — `FileSystem`, `CimProvider`, `RegistryService`, `EnvironmentProvider`, `ScriptInvoker`, `Clock` |
| `Operation` | the method name |
| `Arguments` | `object[]`, in declaration order |

Rules that must hold:

- Seeding is still never recorded, in either sink.
- `$Operations` keeps its own independent 1-based `Sequence`. The journal's
  numbering is global; the per-fake numbering is not.
- A fake created without `-Journal` behaves exactly as it does today.
- Every fake exposes `[string] $ServiceName` so the journal entry and a test can
  both name it without a type literal.

The canonical cross-service assertion, which 03-05's headline test uses:

```powershell
$journal | ForEach-Object { '{0}.{1}' -f $_.Service, $_.Operation } |
    Should -Be @('FileSystem.ReadAllText', 'Clock.GetUtcNow', 'FileSystem.AppendAllText')
```

### IClock

```
GetUtcNow()                 -> [datetime], always UTC
Sleep([int] $Millisecond)   -> void
```

Two methods, both recorded. `Sleep` exists so retry backoff (03-04) is provable
without a test that actually waits: the fake advances its own clock instead.

`New-HDTFakeClock -UtcNow <datetime> [-TickMillisecond <int>] [-Journal]`

- `GetUtcNow()` returns the current fake time, then advances it by
  `-TickMillisecond` (default `0`, so a clock is frozen unless asked otherwise).
- `Sleep(n)` advances the fake time by `n` and returns immediately.
- `Advance(n)` is seeding, not an operation, and is not recorded.
- `TotalSleepMillisecond` accumulates, so a backoff test asserts the total wait
  without waiting.

`New-HDTClock [-Journal]` is the real one: `[datetime]::UtcNow` and
`Start-Sleep -Milliseconds`. Branch-free.

### IFileSystem gains AppendAllText

`AppendAllText([string] $Path, [string] $Content)` — appends, creates the file
when absent, creates parent directories when absent, records like everything
else. Added to `HDTFakeFileSystem` *and* to the new real adapter, and asserted by
the existing contract file so both must implement it.

`New-HDTFileSystem` is the real adapter the 02 verification report asked for
(`New-HDTFileSystem` is already named in shipped help). A `[pscustomobject]` with
`ScriptMethod` members (tests/helpers/README.md F1), recording before the call
can throw, throwing the same `System.IO` exception types the fake throws, writing
UTF-8 **without** a BOM through `System.IO.File`.

### The log record

One `Write-HDTLog` call writes **both** formats (DESIGN 4.4.2). The JSONL object,
in this key order:

```
ts, runId, seq, level, phase, stepIndex, stepName, stepType, component, event,
message, durationMs, data
```

- `ts` — a formatted string, never a raw `[datetime]`.
- `seq` — from the context's monotonic counter, incremented per call. It is
  seeded from `state.json` on resume, which is what makes it survive a reboot.
- `level` — `Error` | `Warning` | `Info` | `Debug`.
- `event` — the DESIGN 4.4.2 vocabulary, enforced with `ValidateSet`:
  `run.start`, `run.end`, `phase.change`, `step.start`, `step.complete`,
  `step.fail`, `step.skip`, `var.resolve`, `native.exec`, `reboot.arm`,
  `reboot.resume`, plus **one addition this phase makes deliberately**:
  `reboot.teardown`, for the autologon teardown in 03-03. Adding it means editing
  the list in **DESIGN 4.4.2 as well** — do that in 03-05's docs task, and no
  other name may be added without the same edit.
  A call with no `-Event` defaults to `message`, which is also in the set and is
  what a custom step's `Write-HDTLog "..."` produces.
- `stepIndex`/`stepName`/`stepType` come from the context, so a custom step's
  output is attributable without the author doing anything (DESIGN 4.4.4).
- `durationMs` and `data` are omitted (not `null`) when not supplied.

The CMTrace line, one physical line, CR/LF in the message replaced by a space:

```
<![LOG[<message>]LOG]!><time="HH:mm:ss.fff+000" date="MM-dd-yyyy" component="<component>" context="" type="<1|2|3>" thread="<id>" file="<file>">
```

`type`: Info and Debug → `1`, Warning → `2`, Error → `3`. `thread` is captured
once when the context is built (`-ThreadId` overrides it, so a test can assert an
exact line). `file` is the caller-supplied `-Source`, defaulting to the step type
or `Engine`.

Writes go to `<LogPath>\HDT.jsonl` and `<LogPath>\HDT.log`, and — when the
context has a `StepLogPath` — the CMTrace line **also** goes to that per-step file
(DESIGN 4.4.3). Nothing else writes a log anywhere (DESIGN 4.4.1).

Verbosity: the context carries `Level`; a call below it is dropped **without
consuming a seq number and without touching the filesystem**. Order of
severity: `Error` < `Warning` < `Info` < `Debug`, so `Level = 'Warning'` emits
Error and Warning only.

### `_HDTLogPath` by phase (DESIGN 4.4.1)

```
Get-HDTLogPath -Phase WinPE  [-TargetVolume]  -> 'X:\HDT\Logs' | '<target>\HDT\Logs'
Get-HDTLogPath -Phase FullOS                  -> 'C:\HDT\Logs'
```

Pure string logic. `-SystemDrive` overrides `C:` so the test does not depend on
the machine it runs on.

### The state document

`state.json`, `schemaVersion` 1. The full shape, which
`schemas/state.schema.json` and `Assert-HDTRunStateDocument` must agree on:

```
schemaVersion  1
runId          the deployment run id (also _HDTRunId)
sequenceId     the sequence's id from sequence.yaml
status         Running | Succeeded | Failed
phase          WinPE | FullOS
leg            1-based; incremented on every resume
seq            the last JSONL seq number written - this is how seq survives a reboot
startedUtc     formatted string
updatedUtc     formatted string
stepIndex      the 1-based index of the NEXT step to run
pauseOnError   bool
variable       name -> value, the resolved variables
step[]         one per flattened step: index, name, type, group (string[]),
               status (Pending|Running|Completed|Failed|Skipped), attempt,
               resumable, startedUtc, endedUtc, durationMs, exitCode, message
autoLogon      { armed, userName, domainName, countSet, secretName, runOnceName }
deploymentPassword   the per-deployment secret, or null once torn down
```

Commands:

```
New-HDTRunState -SequenceId -RunId -Phase [-Variable] [-Step] [-Clock] [-PauseOnError]
Save-HDTRunState -State -Path -FileSystem [-MirrorPath] [-Clock]
Import-HDTRunState -Path -FileSystem
Update-HDTRunStateStep -State -Index -Status [-Attempt] [-ExitCode] [-Message] [-StartedUtc] [-EndedUtc] [-DurationMs]
Test-HDTRunStateAbandoned -State -Clock [-MaxAgeHour 12]
```

- `Save-HDTRunState` stamps `updatedUtc` from the clock, serialises with
  `ConvertTo-Json -Depth 8`, and writes through `IFileSystem.WriteAllText` to
  `-Path` and, when given, to `-MirrorPath` as well. The mirror is DESIGN 4.3's
  "mirrored to the target disk as soon as a formatted volume exists", and it is
  what makes the WinPE→OS transition survivable.
- `Import-HDTRunState` reads through `IFileSystem`, parses with
  `ConvertFrom-Json` (never `-AsHashtable`), validates with
  `Assert-HDTRunStateDocument`, and **rehydrates**: `variable` becomes an ordered
  case-insensitive dictionary and `step` becomes an array in index order. A
  truncated or unparseable file is a terminating `HDTConfigurationError` naming
  the file — a corrupt state document must not be silently treated as "no state",
  because that is the case that would re-run a destructive step.
- `Test-HDTRunStateAbandoned` returns `$true` when `status` is `Succeeded` or
  `Failed`, or when `status` is `Running` and `updatedUtc` is older than
  `-MaxAgeHour`. This is the "state document present but stale" case in the
  ROADMAP M2 autologon block; 03-03's reconcile is its only caller.
</engine_semantics>

`$fs.Operations.Count -eq 0` right after building one.
