<objective>
**M9 — Refresh.** A wipe-and-load launched from the running Windows instead of
from a boot: the machine stages a WinPE onto its own disk, reboots into it,
deletes the old installation, applies the image and comes back. MDT's `REFRESH`,
and the third caller of the `BootToWinPE` transport M7 already built.

It restores **no user state**. DESIGN §1 rules USMT out permanently and this does
not reopen it: `REFRESH` names where the run *started*, not what survived it.

Design: `docs/DESIGN.md` §3.2 and the paragraphs that follow it; requirements:
`docs/ROADMAP.md` M9.

Output: a derived deployment type that a rules document cannot set, a full-OS
entry point for the engine, two new step types, three Refresh-scoped validation
guards, and a shipped `refresh.yaml` that executes end to end against fakes on
both legs.
</objective>

**One mapping, in one private function.** `Get-HDTDeploymentType -Phase` returns
`NEWCOMPUTER` for `WinPE` and `REFRESH` for `FullOS`. Two callers need it —
`Get-HDTMachineFact` publishes it into the variable bag, `New-HDTRunState` stamps
it onto the document that crosses the reboot — and if each carried its own copy
one run could be a REFRESH in its log and a NEWCOMPUTER in its checkpoint.

**No `else` and no default.** The `ValidateSet` is the whole set of legs, so a
third leg added there without a branch here would publish an empty type, and a
test that walks the `ValidateSet` fails the day it lands.

**Decided on the FIRST leg, carried after that.** The *phase* is re-derived every
leg — it decides where the log goes and which steps may run. The *type* is not: a
Refresh's second leg runs in WinPE, and a leg that re-derived would rename the
run halfway through. `Get-HDTMachineFact` takes the carried value when there is
one and derives only when there is not, and says which it did in the provenance —
source `state` with the sentence naming the leg that decided it, or source
`engine` with the property `Phase`.

**`deploymentType` on the state document**, added to `schemas/state.schema.json`
as an optional enum and to `Assert-HDTRunStateDocument`. Optional, because a
document written by an older engine belongs to a run that is still going — and
an absent value must unlock nothing rather than granting a default.

**The resume exception.** `Get-HDTResumePermittedStepType -DeploymentType` returns
`ApplyImage` for `REFRESH` and an empty set for everything else, including an
absent or unknown type. `Test-HDTResumeStepForbidden` gains the parameter and
consults it. `DiskPartition` stays in the forbidden set for every type without
exception — a Refresh reuses the partition Windows was booting from, and
repartitioning would destroy the staged WinPE the leg is running from.

The guard keeps its position **ahead of** the already-completed check. It exists
to disbelieve `state.json`, and a guard placed after that check would be dead
code in precisely the case it exists for.

**Read the type once, above the loop**, and read it with a property-existence
check rather than assuming it: under `Set-StrictMode -Version Latest`, reading a
property an older document does not carry is a terminating error.
