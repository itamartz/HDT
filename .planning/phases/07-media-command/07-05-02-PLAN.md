<objective>
The third defect, and the only genuinely new capability in this phase: the
details pane has a text box and a drop-down and **no browse affordance at all**.
The Output row on a media item is a filesystem path a technician is currently
expected to type from memory.

Add one, in the same shape the pane already uses for the box/list pair: a
`Browse` kind on `New-HDTConsoleField`, a `HasBrowse` `DataTrigger` in the item
template, a button in the template's third column, and a handler in
`New-HDTConsoleView.ps1`.

Purpose: the precedent named for the handler is the driver import's
`Shell.BrowseForFolder` (`New-HDTConsoleView.ps1` ~line 2361) - but that one
picks a FOLDER and this wants a path to an `.iso` FILE that **does not exist
yet**, because `Update-HDTMediaContent` is what creates it. So it is a
`SaveFileDialog`, not `BrowseForFolder` and not an `OpenFileDialog` whose
`CheckFileExists` would refuse the one legal answer. `New-HDTConsoleHost.ps1`
~line 1202 already made exactly this decision for the New Media dialog's own
output box, with the reasoning written above it; this is the same box on the
other door and it gets the same control.

Output: a Browse button that fills the Output row, a closed set of browse kinds
with one place that maps each to a dialog, and a contract that makes the next
field to declare one impossible to half-wire.
</objective>

<design_decisions>

**1. `-Browse` is a KIND, not a bare switch.** `New-HDTConsoleField -Browse
'IsoFile'` with a `ValidateSet`, not `[switch] $Browse`. Two reasons, and the
second is the one that matters:

- A switch would force the view's handler to know that "a browse on a media
  output row means a save dialog filtered to `.iso`" - a decision, inside an
  adapter, where nothing can test it.
- **Rule 8.** A closed set is a thing a contract can walk. `Get-HDTConsoleFieldBrowse`
  answers every member of that set, a test asserts it answers every member, and
  the day somebody adds `'Folder'` the test fails until the mapper learns it.
  A switch gives a sweep nothing to enumerate.

The set has exactly one member today: `'IsoFile'`. Do not add a second
speculatively - `'Folder'` has no caller, and an unused branch is scope this
plan was not asked for. The set-walking test is what makes adding it safe
later.

**2. `Get-HDTConsoleFieldBrowse` is the one place a kind becomes a dialog**, and
it is pure: `-Kind` and `-Current` in, a `[pscustomobject]` out with `Dialog`,
`Title`, `Filter`, `FileName`, `Directory`. No WPF type is touched in it, so it
is unit-testable with no window - the same split `Get-HDTConsoleRemoval` makes
for a confirmation and `Get-HDTConsoleMediaEdit` makes for a typed value.

**3. The button is an ellipsis glyph, not a word.** `Content="&#x2026;"` -
U+2026, which decodes to a character with no letters in it, so the prose-literal
contract passes it honestly rather than by a loophole. There is nothing to
translate: an ellipsis button beside a path box is the Windows convention, the
label column already says `Output`, and the help dot beside it already carries
the sentence. **No `ToolTip`, no `AutomationProperties.Name` literal** - both
would be untranslatable prose that the contract's regex happens not to catch,
which is worse than prose it does catch.

**4. A Browse on a row that writes no key is refused at build time.**
`New-HDTConsoleField` throws when `-Browse` is given without `-Property`, and
when it is given with `-Choice` or `-Check`. A button that opens a file picker
and then has nowhere to put the answer is a defect that would look like a UI
that "does nothing"; a refusal at the row builder names it at the line that
caused it.

**5. `HasBrowse` is a separate boolean from `Kind`.** Browse is an ADJUNCT to a
text row, not a fourth kind of row: the box is still the control, the button
sits beside it in the third column. `Kind` stays `'Text'`. This mirrors
`HasHint`, which is also an adjunct, and keeps `Kind`'s "one string cannot
contradict itself" property intact.

**6. The button reaches its box by `ElementName`, not by walking the tree.**
`Tag="{Binding ElementName=HDTDetailBox}"` - a `DataTemplate` has its own name
scope, so this resolves to the box on the same row and nothing else. The
alternative, walking up to the `Grid` and back down for a `TextBox`, is more
code and silently finds the wrong control the day the template gains a second
one.

</design_decisions>

```powershell
        # comment says the same thing for the same reason.
        if (@($row.PSObject.Properties.Match('Browse')).Count -eq 0) { return }

        $kind = [string] $row.Browse
        if ([string]::IsNullOrEmpty($kind)) { return }

        $box = $button.Tag -as [System.Windows.Controls.TextBox]
        if ($null -eq $box) { return }

        $ask = & $call 'Get-HDTConsoleFieldBrowse' -Kind $kind -Current ([string] $box.Text)

        if ([string] $ask.Dialog -ne 'Save') { return }

        $picker = New-Object -TypeName Microsoft.Win32.SaveFileDialog
        $picker.Title = [string] $ask.Title
        $picker.Filter = [string] $ask.Filter
        $picker.OverwritePrompt = $false

        if (-not [string]::IsNullOrEmpty([string] $ask.Directory)) {
            $picker.InitialDirectory = [string] $ask.Directory
        }

        if (-not [string]::IsNullOrEmpty([string] $ask.FileName)) {
            $picker.FileName = [string] $ask.FileName
        }

        # CANCEL WRITES NOTHING, and that is the rule rather than a convenience:
        # an Output left empty is New-HDTMedia's default to fill, and a picker
        # that put a path in on the way out would turn a deliberate blank into
        # a decision nobody made.
        if ($picker.ShowDialog() -ne $true) { return }

        $picked = [string] $picker.FileName
        if ([string]::IsNullOrWhiteSpace($picked)) { return }

        # THE CONTROL, THEN THE SOURCE. The row is a PSCustomObject and raises
        # no PropertyChanged, and this TextBox updates its source on LostFocus -
        # which a click on a button beside it does not cause. Writing $row.Value
        # instead would leave the box showing the old path.
        $box.Text = $picked

        $binding = $box.GetBindingExpression([System.Windows.Controls.TextBox]::TextProperty)
        if ($null -ne $binding) { [void] $binding.UpdateSource() }

        if (-not (& $call 'Test-HDTConsoleRowCommit' -Row $row -Typed $picked)) { return }

        & $writeRow $row $picked { param([string] $text) $box.Text = $text }.GetNewClosure()
    }.GetNewClosure())
```
