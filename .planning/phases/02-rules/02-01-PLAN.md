<verified_facts>
Probed on this machine on 2026-08-13. These are facts, not guesses — do not
re-litigate them, and do not design around a different assumption.

**F1. A real adapter must be a `[pscustomobject]` with `ScriptMethod` members,
not a PowerShell class.** Classes dot-sourced from `Private/*.ps1` or
`Public/*.ps1` into `Hephaestus.psm1` are the known-flaky path across `-Force`
re-imports (01-03 SUMMARY). A `pscustomobject` carrying `ScriptMethod` members
duck-types to the same contract, reloads cleanly, and works identically under
pwsh 7.5.8 and Windows PowerShell 5.1.26100.8655.

**F2. `Get-Member -MemberType Method` does NOT list a `ScriptMethod`.** Verified.
The existing "exposes every method the contract requires" assertions therefore
fail against a real adapter. The fix is `-MemberType Method, ScriptMethod` in
every contract file. Per `tests/helpers/README.md` section 6, when a real adapter
cannot pass a contract test the *contract* is fixed — never forked.

**F3. A `ScriptMethod` returning an array collapses a single-element array to a
scalar.** `return [object[]] @($x)` yields `-is [System.Array]` = `$false`.
`return ,([object[]] @($x))` yields `$true` for 0, 1 and 28 elements, on both
engines. The unary comma is mandatory in every array-returning `ScriptMethod`;
the existing contract test `returns an array even for a single instance` proves
it.

**F4. A `ScriptMethod` dispatches optional arguments positionally.** One
`ScriptMethod` named `GetInstance` with `param([string] $First, [string]
$Second)` serves both contract overloads: when `$Second` is empty the call was
the one-argument form, so `$First` is the class name and the namespace is
`root/cimv2`.

**F5. Available on this machine, all queried successfully:**

| Class / source | Result |
|---|---|
| `Win32_SystemEnclosure` | 1 instance, `ChassisTypes = 10` (laptop), `SerialNumber = PF3EKMR0` (real — sanitise) |
| `Win32_NetworkAdapterConfiguration` | **28** instances, **9** with `IPEnabled = $true`, several with `DefaultIPGateway = $null` |
| `Win32_Tpm` in `root/cimv2/security/microsofttpm` | 1 instance, `SpecVersion = "2.0, 0, 1.38"` |
| `$env:firmware_type` | `UEFI` |
| `HKLM:\SYSTEM\CurrentControlSet\Control\SecureBoot\State` → `UEFISecureBootEnabled` | `1` |
| `Win32_ComputerSystem.SystemSKUNumber` | `LENOVO_MT_82RF_BU_idea_FM_Legion 5 Pro 16IAH7H` |

Full `Win32_NetworkAdapterConfiguration` JSON is 58 KB; projected to the
properties below it is 13.5 KB. Project it.

**F6. `New-HDTFakeCimProvider -FixturePath` seeds every `*.json` in one
directory into `root/cimv2` only**, and uses `Get-ChildItem -Filter '*.json'
-File`, so subdirectories are ignored. `Win32_Tpm` lives in another namespace
and therefore needs a new parameter (Task 1), not a subdirectory.
**F7. `Get-CimInstance` does NOT name the class in its "invalid class"
message.** Probed on both engines: the message is exactly `Invalid class ` — the
class name is absent. The existing `ICimProvider` contract asserts
`Should -Throw -ExpectedMessage '*Win32_NoSuchClassHDT*'`, and 01-03 deliberately
proved that assertion goes red when the class name is removed, so it is
load-bearing. **The real adapter therefore has to supply the class name itself**
(Task 2d) — an earlier draft of this plan said "do not add a catch", which was
wrong and would have left the contract failing with no sanctioned fix.

**F8. An exception thrown inside a `ScriptMethod` reaches the caller wrapped.**
Probed on both engines:

| Thrower | What the caller catches |
|---|---|
| PowerShell class method (the fakes) | the original type, e.g. `System.IO.FileNotFoundException` |
| `ScriptMethod` on a `pscustomobject` (the real adapters, F1) | `System.Management.Automation.MethodInvocationException`, whose `InnerException` is `System.Management.Automation.RuntimeException`, whose `InnerException` is the original type |

So `Should -Throw -ExceptionType ([System.IO.FileNotFoundException])` passes
against a fake and **fails against a real adapter**, which breaks
`tests/helpers/README.md` section 5 ("the fake throws the same exception type the
real adapter throws; contracts assert `-ExceptionType`") at exactly the boundary
this plan crosses first. Every contract assertion about an exception *type* must
therefore unwrap to the innermost exception:

```powershell
$record = $null
try { $script:invoker.Invoke($missing, @{}) } catch { $record = $_ }

$record | Should -Not -BeNullOrEmpty
$inner = $record.Exception
while ($null -ne $inner.InnerException) { $inner = $inner.InnerException }
$inner | Should -BeOfType ([System.IO.FileNotFoundException])
```

The loop is a no-op for a class-based fake and unwraps twice for a real adapter,
so one assertion serves both rows. Assertions about a *message* need no unwrapping:
`MethodInvocationException.Message` embeds the inner message, so
`-ExpectedMessage '*...*'` keeps working.

**F9. `Describe '<Name>' -ForEach $registry -Skip:$Skip` does NOT skip.** Verified
against Pester 5.7.1: `-Skip` is bound once, where `Describe` is called, before
`-ForEach` binds the row's keys — so `$Skip` is unset there and every row runs.
A row marked `Skip = $true` ran anyway. What *does* work is a `Context` inside the
block, where the row's keys are in scope:

```powershell
Describe 'IRegistryService contract: <Name>' -ForEach $script:HDTImplementation {
    Context 'implementation' -Skip:$Skip {
        BeforeEach { $script:registry = & $Factory $script:repoRoot }
        It '...' { }
    }
}
```

Verified: the `Skip = $true` row reports its tests as skipped, the other runs them.
`-Skip:` on a `Describe` that has **no** `-ForEach` is fine, because the variable is
then a file-scope one evaluated at discovery — that is why 02-02's schema contract
may keep its file-level skip.

**F10. PSScriptAnalyzer fails every `New-HDT*` function without a suppression.**
`PSUseShouldProcessForStateChangingFunctions` is a Warning, and
`PSScriptAnalyzerSettings.psd1` sets `Severity = @('Error', 'Warning')` with
`ExcludeRules = @()`, so it breaks `build.ps1 -Task lint` and therefore `-Task ci`.
Verified against a stub adapter. The two existing fakes already carry the
suppression; the four **real** adapters in Task 2d need it too, and so does
`New-HDTErrorRecord` in plan 02-02.

`tests/helpers/README.md` exactly: recorded operations, error parity, factory
only, contract-as-test with a discovery-time registry.

### IRegistryService (read subset)

| Method | Behaviour |
|---|---|
| `[bool] TestPath([string] $Path)` | `$true` if the key exists |
| `[object] GetValue([string] $Path, [string] $Name)` | the value, or **`$null`** when the key or the value is absent — absence is normal (a BIOS machine has no `SecureBoot\State` key) and must never throw |

Fake-only seeding: `[void] SetValue([string] $Path, [string] $Name, [object] $Value)`,
not recorded. Paths are PowerShell provider paths (`HKLM:\SYSTEM\...`); normalise
by upper-casing and accepting `HKEY_LOCAL_MACHINE\` as a synonym for `HKLM:\`.

**Phase 03 extends this interface with write methods** (`SetValue` as a recorded
operation, `RemoveValue`, `RemoveKey`) for the autologon lifecycle in DESIGN 4.5.
Leave room for that: do not name the read-only methods in a way that has to
change later, and say so in the contract file header.

### IEnvironmentProvider

| Method | Behaviour |
|---|---|
| `[string] GetVariable([string] $Name)` | the environment variable's value, or `$null` when it is not set. Name comparison is case-insensitive |

Fake-only seeding through the factory's `-Variable` hashtable.

### IScriptInvoker

| Method | Behaviour |
|---|---|
| `[object] Invoke([string] $Path, [System.Collections.IDictionary] $Variable)` | runs the script and returns its **last output object**; throws `[System.IO.FileNotFoundException]` when the script does not exist |

The invoked script receives the currently resolved variables as `-Variable`.
The real adapter resolves a relative `$Path` against its `-Root` (the workspace
root), so `Scripts\Get-ComputerName.ps1` from `rules.yaml` works from either a
share or standalone media.

### Recording (all three, per tests/helpers/README.md section 4)

`$Operations` of `[pscustomobject]` with `Sequence` / `Operation` / `Arguments`,
`GetOperationName()`, read-only calls recorded, recorded before the method can
throw, seeding never recorded.

|---|---|---|

| `HDTModel` | `Win32_ComputerSystem.Model` | trimmed; when empty, `Win32_BaseBoard.Product` |
