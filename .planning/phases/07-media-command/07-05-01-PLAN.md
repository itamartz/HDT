<objective>
Two of the three defects in the media details pane, both of them the same
mistake: a value the document constrains to a closed set was drawn as a box
somebody types into.

**Selection profile becomes a list of this share's profile ids.** A typed
profile name that is wrong is not refused by anything a technician can see -
`Set-HDTMedia` refuses an unknown id, but the failure mode this guards against
is a *legal* id that is the wrong one, which produces a media item whose disc
has no content. `HDTNewMedia.xaml` already makes this argument in its own header
comment for why ITS profile picker is a ComboBox; the details pane is the other
door to the same key and it was left a box.

**Enabled becomes a list of `true` and `false`.** It is drawn as a box holding
`yes`/`no` today - the sentence that used to be inside the value was moved to
the `-Hint` in 07-04, so the live splice defect is already gone. What is left
is that `yes` is not what the document holds: `media.yaml` carries a bare YAML
boolean, `Assert-HDTMediaDocument` refuses a quoted one, and a pane that shows
a different word than the file does is a pane a technician has to translate.

Purpose: the pane became writable in 07-04 and was drawn as three plain text
boxes. Making the two closed-set rows lists costs no new markup - the
`HasChoice` DataTrigger and the `ComboBox.SelectionChangedEvent` handler that
writes a pick are both already in this window, built for the step editor's log
level - so this is a row-builder change and a wiring change, not a UI change.

Output: a media item's details pane where the only free-text rows left are the
two that genuinely are free text (Description, Output), and a proven round trip
from a pick in the window to a boolean on disk and back through `Get-HDTMedia`.
</objective>

<design_decisions>

**1. Enabled is a DROPDOWN, not a tick box, and that is a deliberate deviation
from the house pattern.** Every other yes/no in this console is
`New-HDTConsoleField -Check` - the Options tab's Disabled and Continue on
error, and a step's `wipe`, `expand`, `recoveryPassword`, `wait`.
`New-HDTConsoleField`'s own help says so: "YES-OR-NO, WHICH IS A TICK BOX
EVERYWHERE ELSE IN THIS WINDOW." **The user asked for a dropdown here
specifically, so this one is a dropdown by explicit instruction rather than by
the house pattern.** Record that in the code comment above the field, in those
terms, so the next person to sweep this window for consistency finds the reason
instead of "fixing" it. Do not change any other row to match, and do not change
this one to a tick box because the pattern says so.

`New-HDTConsoleField`'s `Kind` already resolves this cleanly with no change:
`if ($Choice.Count -gt 0) { 'Choice' } elseif ($Check) { 'Check' }` - a list
wins over a tick box - so passing `-Choice @('true','false')` and no `-Check`
is all it takes.

**2. The words are `true` and `false`, not `yes` and `no`.** They are what
`media.yaml` holds, what `Set-HDTMedia` writes, and what
`Assert-HDTMediaDocument` accepts. A pane showing `yes` over a file saying
`true` asks a technician to hold two vocabularies for one key.

**3. `Get-HDTConsoleMediaEdit` keeps reading `yes`/`no`/`1`/`0`.** Nothing in
the pane can produce them any more, but the function is a public-shaped
decision with its own test file, and narrowing it would break a caller for no
gain. Only the refusal message changes, to name `true` and `false` - because
that is now what the pane offers, and the message is what a technician reads
when something else reaches it.

**4. `-SelectionProfile` takes the profile OBJECTS, not a string array.** That
is exactly what `$Workspace.SelectionProfile` is, and mapping `.Id` in one
place - inside `Get-HDTConsoleMediaNode`, under test - beats mapping it at the
call site where nothing checks it. Default `@()`, so the parameter is not
mandatory and no other caller breaks.

**5. An empty profile list degrades to a text box, and that is correct.** If
`Choice` ends up empty (no profiles readable AND the media names none), `Kind`
falls back to `'Text'` and the row is the box it is today. A combo with nothing
in it is a control that cannot be used; a box can at least be typed into, and
`Set-HDTMedia` will refuse a bad id with a message naming every legal one. In
practice this cannot happen from a healthy share - `Get-HDTSelectionProfile`
falls back to the built-ins - but `$Workspace.SelectionProfileFailure` is a
real state and the row must survive it.

</design_decisions>
