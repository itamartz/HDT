<objective>
Create `HDTDeploymentMethod` as a name the module knows about: one command that
decides it, one row in the variable map that documents it, and one refusal in
the rules validator that stops an administrator declaring it.

Nothing in this plan publishes a value or changes a deployment's behaviour. It
makes the name exist, correctly, on every surface that enumerates names. Plan 02
publishes it; plan 03 reads it.

Purpose: MDT carries two variables here and HDT has only one of them
(`HDTDeploymentType` = NEWCOMPUTER). The missing one is `DeploymentMethod`, and
everything the phase does afterwards reads it rather than sniffing at a provider
object.

Output: `Get-HDTDeploymentMethod`, a map row, a validator refusal, and the
manifest/reference/contract updates that make each of those real.
</objective>

<design_decisions>
Two calls this plan makes, stated once here so the tasks can be short.

**1. `Get-HDTDeploymentMethod` is a PUBLIC command, not a private helper.**
`src/Hephaestus/Payload/Start-HDTDeployment.ps1` is a script, not part of the
module — its own comment at ~line 1330 says so: *"It reaches the engine through
Import-Module Hephaestus, which imports the MANIFEST — so the only names that
exist here are the ones in FunctionsToExport."* Plan 02 calls it from that file,
so it must be exported. `tests/contract/PayloadExportedCommand.Contract.Tests.ps1`
enforces exactly this.

The cost is the four surfaces a new public command has to reach — manifest,
bundle, `docs/command-categories.psd1`, `docs/command-reference.html` — and
`tests/contract/CommandReference.Contract.Tests.ps1` already asserts the page
against the SET, so a missed one fails the gate rather than shipping quietly.

**2. `Writable` stops being derived from the underscore and becomes a fact.**
`Get-HDTVariableMap.ps1:433` computes `Writable = (-not $entry.HDTName.StartsWith('_'))`.
`HDTDeploymentMethod` has no underscore — MDT's name is `DeploymentMethod` and a
step condition wants `%HDTDeploymentMethod%` — but it is not writable. So the
row carries `Writable = $false` explicitly, exactly the way `Secret` is already
an opt-out key on a handful of rows: absent means "use the prefix rule", present
means "this row means it".

**And then the refusal is driven by the map, not by a name.** Widening
`Assert-HDTRuleDocument`'s `_`-prefix check to "every name the map marks not
writable" is what makes this a SET (CLAUDE.md rule 8). The next engine-origin
variable is refused the day its map row lands, with no second edit to remember.
</design_decisions>
