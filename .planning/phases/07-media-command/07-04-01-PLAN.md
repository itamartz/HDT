<objective>
Put **New Media** on the console's right-click menu, off the `Media` category, the
way **New Task Sequence** is off `TaskSequences` and **New Application** is off
`Applications`. One dialog - id, name, which selection profile projects onto the
disc, where the ISO goes - backed by `New-HDTMedia`, which plan 07-01 already
built and unit-tested. This plan writes no new engine command; it writes the
console's door to the one that exists.

Purpose: phase 07-03 shipped `Update Media Content` and wrote down, in three
places, that New Media and Remove Media were a **deliberate deferral** - a
command an administrator can only reach from a prompt is half a feature, and
this repository has shipped that exact half-feature twice before (Windows
Updates, and the media node itself before 07-03). This plan and 07-04-02 close
it.

Output: `HDTNewMedia.xaml`, the private helpers behind it, the `ShowNewMedia`
host method, and the menu wiring that reaches all three - plus the tests that
prove a person with a mouse can actually get there.
</objective>

<design_decisions>
**1. One dialog, four fields, no `Description`.** The phase names exactly
"id, name, selection profile picker, output path." `New-HDTMedia -Description`
stays unset from this dialog - an administrator who wants one still has
`Set-HDTMedia`, and a fifth optional field is scope this plan was not asked for.

**2. The selection profile list is never typed, only chosen.** Exactly the
reason `HDTBootImage.xaml`'s own profile box is a `ComboBox` and not a
`TextBox`: a typed name that is wrong builds a media item with **no content on
the disc**, and `New-HDTMedia` already refuses an unknown profile at write time
- but refusing on the dialog's last press is a wizard that fails once every
other answer has been given. The box is seeded from `Get-HDTSelectionProfile`
on THIS share, built-ins included, so every value it can hold is one
`New-HDTMedia` will accept.

**3. Output gets a Browse button, id and name do not.** An id and a name are
typed; an ISO's destination is a path on disk, and every other path field in
this console (`HDTBootImageBackgroundBox`, `HDTBootImageUnattendBox`,
`HDTContentSourceBox`) pairs a `TextBox` with a Browse button rather than
asking for one to be typed correctly. Left empty, `New-HDTMedia` fills in
`Media\<id>\HDT_<id>.iso` itself - the dialog does not have to duplicate that
default, only leave the box legitimately empty and say so in its hint.

**4. `New-HDTConsoleView` gates the item on `-NewMediaXaml`, exactly like New
Task Sequence and Import Windows Update, and for their reason: an item that
cannot open its window is one somebody presses to find out nothing happens.**
`Show-HDTConsole` is the only real caller and always supplies the shipped
file, so this gate is only ever seen by a test or a probe built another way -
which is precisely how the Windows Updates half-feature went unnoticed for as
long as it did.
</design_decisions>
