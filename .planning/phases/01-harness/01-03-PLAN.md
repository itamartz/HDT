<verified_facts>
Probed on this machine: **PowerShell classes defined inline in a `.psm1`,
returned through a factory function, work identically under 5.1 and 7** —
including method overloads, `[System.Collections.ArrayList]::new()`, and
throwing typed exceptions such as `[System.IO.FileNotFoundException]`.

Two consequences that are requirements, not suggestions:
1. **Define the classes inline in `HDTFakes.psm1`, not in dot-sourced `.ps1`
   files.** Class definitions dot-sourced into a module are the known-flaky path
   across `-Force` re-imports.
2. **Tests must obtain fakes only through the factory functions.** Never write
   `[HDTFakeFileSystem]::new()` and never use the class name as a type literal in
   a test file — a type literal binds to whichever dynamic assembly was loaded
   first and breaks on module reload.
</verified_facts>

<service_contracts>
These are the contracts this plan establishes. Later phases add real adapters
that must satisfy them unchanged.

### IFileSystem

| Method | Behaviour |
|---|---|
| `[bool] TestPath([string] $Path)` | true if a file or directory exists at Path |
| `[string] ReadAllText([string] $Path)` | file contents; throws `[System.IO.FileNotFoundException]` if absent; throws `[System.UnauthorizedAccessException]` if Path is a directory |
| `[void] WriteAllText([string] $Path, [string] $Content)` | writes, overwriting; **creates missing parent directories** |
| `[void] CreateDirectory([string] $Path)` | idempotent; creates intermediate directories |
| `[void] RemoveItem([string] $Path, [bool] $Recurse)` | **no-op if Path does not exist**; throws `[System.IO.IOException]` for a non-empty directory when `$Recurse` is `$false` |
| `[void] CopyItem([string] $Source, [string] $Destination)` | file copy; throws `[System.IO.FileNotFoundException]` if Source is absent; creates missing destination parents |
| `[string[]] GetChildItem([string] $Path)` | **immediate** children as full paths, sorted ordinal; throws `[System.IO.DirectoryNotFoundException]` if Path is absent |
| `[long] GetLength([string] $Path)` | byte length; throws `[System.IO.FileNotFoundException]` if absent |

Path handling: normalise with `[System.IO.Path]::GetFullPath()`, trim a trailing
directory separator, compare case-insensitively (Windows semantics). Never touch
the real filesystem from the fake.

### ICimProvider

| Method | Behaviour |
|---|---|
| `[object[]] GetInstance([string] $ClassName)` | instances from the default namespace `root/cimv2` |
| `[object[]] GetInstance([string] $Namespace, [string] $ClassName)` | instances from an explicit namespace (needed for `root/cimv2/security/microsofttpm` / `Win32_Tpm`, DESIGN §3.2) |
| `[void] AddInstance([string] $Namespace, [string] $ClassName, [object[]] $Instance)` | fake-only seeding |

A class that was never seeded **throws** with a message containing the class
name (matching `Get-CimInstance`'s behaviour on an invalid class). A class seeded
with an empty array returns an empty array — that is how "class exists, no
instances" is expressed.

### Recording (both fakes, and every fake after them)

- `[System.Collections.ArrayList] $Operations` — one `[pscustomobject]` per call
  with `Sequence` (1-based), `Operation` (the method name), `Arguments` (object[]).
- `[string[]] GetOperationName()` — the ordered operation names, which is what
  DESIGN §12.2.1's "assert the ordered list of operations" assertions consume.
- Read-only methods (`TestPath`, `ReadAllText`, `GetChildItem`, `GetLength`,
  `GetInstance`) record too — provenance and query-order assertions need them.
</service_contracts>
