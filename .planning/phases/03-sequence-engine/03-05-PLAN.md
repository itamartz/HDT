### `ConvertTo-HDTReport`

```
ConvertTo-HDTReport -JsonlPath <string> -Path <string> -FileSystem <object>
                    [-State <object>] [-Title <string>] [-Timestamp <datetime>]
    -> [string]  the path it wrote
```

- Reads the JSONL through `IFileSystem.ReadAllText` and parses **line by line**.
  A blank line is ignored; a line that does not parse is **counted and reported
  in the report itself**, never fatal. A truncated last line is the normal state
  of a log from a machine that died, which is exactly when somebody opens the
  report.
- Emits one **self-contained** HTML file: inline CSS, no script, no CDN, no
  external font. A report is read from a USB stick, from a share, and from a
  machine with no network — anything external is a report that renders blank when
  it matters.
- Sections, in order:
  1. **Header** — run id, sequence id, computer name, phases seen, start and end,
     duration, outcome.
  2. **Summary** — counts of completed / failed / skipped / total, the failing
     step called out.
  3. **Steps** — index, group, name, type, status, attempts, duration, exit code,
     message, in index order, with the status colour-coded.
  4. **Legs** — the `reboot.arm` and `reboot.resume` records, so a multi-leg
     deployment reads as a timeline.
  5. **Variables** — the `var.resolve` records with their source and rule, which
     is DESIGN 3.1's "explains every value" surfacing in the report.
  6. **Log** — every record, with `level`, `seq`, `event` and message.
- **Everything is HTML-escaped**: `&`, `<`, `>`, `"`, `'`. A step message
  containing `<` is normal (a command line, an XML fragment), and a report that
  breaks on it is worse than no report. `ConvertTo-HDTHtmlText` is the private
  helper and has its own tests.
- It writes through `IFileSystem.WriteAllText` — UTF-8, no BOM, with
  `<meta charset="utf-8">` in the head.
- **The deployment password never appears.** The report is built from the JSONL,
  which never carries it, and from `-State`, from which the report reads only
  `status`, `leg` and the step records. Assert it.

### The demonstration sequence — `samples/workspace/TaskSequences/DEMO-M2/sequence.yaml`

One sequence serves the headline test and the live demonstration. It uses only
M2 step types, does nothing destructive, and exercises every M2 behaviour:

```yaml
schemaVersion: 1
id: DEMO-M2
name: M2 demonstration - sequencing, conditions, retry and reboots
description: >
  Exercises grouping, conditions, retry with backoff, runIn filtering,
  continueOnError, two reboots and resume. Nothing it does is destructive.
variables:
  HDTDemoRole: workstation
  HDTInstallStage: none

steps:
  - group: Preinstall
    steps:
      - name: Announce
        type: NoOp
        message: "Starting %HDTComputerName%"
      - name: Record Stage
        type: SetVariable
        variables:
          HDTInstallStage: preinstall
      - name: Flaky Preflight
        type: NoOp
        failAttempt: 1
        retry: { count: 2, delaySeconds: 5, backoff: exponential }
      - name: Reboot Into Install
        type: Restart

  - group: Install
    condition: '"%HDTInstallStage%" != "skip"'
    steps:
      - name: Record Stage
        type: SetVariable
        variables:
          HDTInstallStage: install
      - name: Run Installer
        type: CommandLine
        command: cmd.exe /c echo HDT demo installer
        successCodes: [0]
        rebootCodes: [3010]
      - name: Reboot After Install
        type: Restart

  - group: State Restore
    condition: '"%_HDTPhase%" == "FullOS"'
    steps:
      - name: Corp Baseline
        type: PowerShell
        script: Scripts\Set-CorpBaseline.ps1
      - name: WinPE Only Task
        type: NoOp
        runIn: WinPE
      - name: Optional Task
        type: NoOp
        fail: true
        continueOnError: true
      - name: Finish
        type: NoOp
        message: Deployment complete

  - group: Server Only
    condition: '"%HDTDemoRole%" == "server"'
    steps:
      - name: Install Roles Placeholder
        type: NoOp
      - name: Configure Roles Placeholder
        type: NoOp
```

Three legs result: **leg 1 in WinPE** runs `Preinstall` and stops at the first
`Restart`; **leg 2 in FullOS** runs `Install` and stops at the second;
**leg 3 in FullOS** runs `State Restore` — skipping `WinPE Only Task` on phase,
tolerating `Optional Task`'s failure — and skips both steps of `Server Only` on
the group condition. `Flaky Preflight` proves retry. `Corp Baseline` proves the
`PowerShell` step. `Run Installer` proves `CommandLine`.

`samples/workspace/Scripts/Set-CorpBaseline.ps1` is a **user** script, so it
carries no `HDT` prefix (`samples/` is outside `Get-HDTSourceFile`, exactly as
`Get-ComputerName.ps1` already is). It takes `param($Variable)`, writes one
`Write-Host` line — proving DESIGN 4.4.4's transcript capture — and emits nothing
else.

### The headline assertion

Three assertions together are "the exact ordered list of operations it would have
performed":

1. **Side effects**, across all three legs, from the shared journal filtered to
   `RegistryService`, `LsaService`, `PowerService`, `ProcessService` and
   `ScriptInvoker`:

```powershell
$journal |
    Where-Object { @('RegistryService','LsaService','PowerService','ProcessService','ScriptInvoker') -contains $_.Service } |
    ForEach-Object { '{0}.{1}' -f $_.Service, $_.Operation } |
    Should -Be @(
        # leg 1: arm for the first reboot
        'RegistryService.RemoveValue'    # a stale registry DefaultPassword, defensively
        'RegistryService.SetValue'       # AutoAdminLogon
        'RegistryService.SetValue'       # DefaultUserName
        'RegistryService.SetValue'       # DefaultDomainName
        'RegistryService.SetValue'       # AutoLogonCount
        'LsaService.SetSecret'           # DefaultPassword
        'RegistryService.SetValue'       # RunOnce\HDTResume
        'PowerService.Restart'
        # leg 2: the installer, then arm again
        'ProcessService.Start'
        ...
        # leg 3: the user script, then the teardown checklist
        'ScriptInvoker.Invoke'
        'RegistryService.RemoveValue'    # AutoAdminLogon
        ...
        'LsaService.RemoveSecret'
        'RegistryService.RemoveValue'    # RunOnce\HDTResume
    )
```

   Write the list out in full, with a comment per line. It is long, and that is
   the point: the list **is** the specification of what HDT does to a machine, and
   a diff on it is how a future refactor announces that it changed behaviour.

2. **The step outcomes**, from the state document: the ordered
   `index/name/status` list, every step accounted for exactly once.

3. **The event stream**, from the JSONL: the ordered `event` list, with `seq`
   strictly increasing across all three legs.

`BeforeAll` builds, once:

```powershell
$script:journal = [System.Collections.ArrayList]::new()
$script:fs      = New-HDTFakeFileSystem -Journal $script:journal -File @{
                      'C:\ws\TaskSequences\DEMO-M2\sequence.yaml' = (Get-Content <sample> -Raw) }

$script:power    = New-HDTFakePowerService    -Journal $script:journal
$script:process  = New-HDTFakeProcessService  -Journal $script:journal -Result @{
                      'cmd.exe /c cmd.exe /c echo HDT demo installer' = @{ ExitCode = 0; StandardOutput = 'HDT demo installer' } }
$script:invoker  = New-HDTFakeScriptInvoker   -Journal $script:journal -Result @{
                      'Scripts/Set-CorpBaseline.ps1' = $null } -Transcript @{
                      'Scripts/Set-CorpBaseline.ps1' = @('applying corporate baseline') }
```

then drives **three legs**, each in its own `It`-free helper so the assertions
read cleanly:

- **Leg 1** — `Phase = WinPE`, a fresh run state from the imported sequence, log
  path `X:\HDT\Logs`. Call `Invoke-HDTTaskSequence`. Expect `RebootPending`.
- **Leg 2** — read `state.json` back out of the fake with `Import-HDTRunState`,
  build a new log context seeded with `$state.seq`, `Phase = FullOS`, log path
  `C:\HDT\Logs`. Call again with `-State`. Expect `RebootPending`.
- **Leg 3** — same again. Expect `Succeeded`.

The state is deliberately re-read from the fake filesystem between legs rather
than passed in memory: that is what a reboot does, and passing the object would
prove nothing about the document.
